## 一、对 Gate 顺序的修正：先打 Gate 1，别先打 Gate 0

README 里排的是 Gate 0 → 1 → 2。**执行顺序应该反过来。**

理由：Gate 0（徒步视频 → 度量三维网格）几乎必然通过——它就是跑一个已发布的模型。
Gate 1（多条骑行视频配准出三维轨迹）**既是核心风险，又是唯一的护城河**。
先花两周做 Gate 0，等于把"这个项目到底成不成立"的答案往后推两周。

**新的第一步：Gate 1 Spike —— 一次纯粹的证伪测试。**

### 关键设计：从"分叉线"开始，而不是从 30cm 开始

README 里 Gate 1 的通过条件写的是横向偏移差 ≥ 30cm。**这个起点太苛刻，而且没有免费真值。**

改成两段：

| | 场景 | 信号量级 | 真值来源 |
|---|---|---|---|
| **1a（先做）** | 有明确 A 线 / B 线分叉的路段（岩石区绕行、内外线、跳台 vs 绕行） | **~2 米** | **肉眼可见**——你能直接看出这个人走了左边那个人走了右边 |
| **1b（后做）** | 同一条线上的细微差异 | ~30cm | 需要交叉验证 |

**1a 的价值在于它有免费且无争议的真值。** 如果 pipeline 连一个 2 米的明显分叉都还原不出来，它永远还原不出 30cm，可以当场止损。
反过来 1a 通过了，才值得投入去解 1b。

### 再关键一点：不需要六自由度位姿，只需要 (s, d)

产品真正要的不是完整的相机 6DoF 轨迹，而是**赛道曲面上的二维坐标**：

- `s` = 沿赛道中心线的弧长（我到哪了）
- `d` = 相对中心线的横向偏移（我走的偏左还是偏右）

这个要求比全局 6DoF 重定位弱得多，也稳健得多——高度、俯仰、滚转的漂移不影响 `(s, d)`。
**Gate 1 的评估指标应该定义在 `(s, d)` 上，不是在位姿误差上。**
这同时也给了 Gate 1 失败时的中间退路：全 6DoF 做不到 ≠ `(s, d)` 做不到。

## 二、Spike 的具体做法

### 数据：不用先去拍
公开的同赛道多车手 POV 视频已经足够做 1a。候选来源：Vital MTB 的 helmet cam 板块、hcracer.com、世界杯赛道（Fort William / Val di Sole 之类，同一场比赛几十个车手的车载）、Whistler A-Line 这种名线。

**选段原则**：挑 **20–40 秒**的片段，不要整条赛道。要有明确的 A/B 分叉。片段短意味着重建快、迭代快、显存不炸。

> ⚠️ 版权/ToS：抓 YouTube 做研究是灰区。开发阶段可以用，但一旦要发表或商业化，需要换成
> BKXC 那份 CC BY 4.0 的第一人称 MTB 数据集（2160p30，但**单车手**——只能验证重建，验证不了配准），
> 或者直接找本地车队签同意书。**这件事越早解决越好，别等到有结果了才发现数据不能用。**

### 管线
1. **建图**：用其中最清晰的一条（或几条）跑 **Depth Anything 3**（`da3 video` / `da3 auto`），导出 ply/glb
2. **重定位**：其余各条用 **hloc**（SuperPoint + LightGlue）配准进这个图
3. **投影**：拟合赛道中心线，把每条轨迹投影成 `(s, d)` 剖面
4. **判读**：在分叉点上，`d` 的分离是否与肉眼所见一致（左/右、量级 ~2m）

### 通过条件
分叉点上各条轨迹的 `d` 分离方向 **100% 与肉眼一致**，量级误差 < 50%。
低于此 → 止损，或退到 `(s, d)` 更弱的表示 / Racecraft 式一维时间对比。

## 三、算力：本机跑不动，租 GPU

**现状**：MacBook Pro M5 Pro / 18 核 / 48GB 统一内存 / **无 CUDA** / 磁盘仅剩 ~52GB / torch 未安装。

- **DA3 官方文档没有提及 MPS 或 CPU 支持**。Apple Silicon 上大概率能凑合跑但会很痛（算子缺失 + 极慢）
- hloc / COLMAP 能在 CPU 上跑，但慢
- **DA3-Streaming 号称 <12GB 显存就能处理超长视频序列** → 一块 4090 / A10 绰绰有余，约 $0.3–0.7/小时

**建议**：本机只做短片段的代码调试，完整管线跑租来的 GPU（RunPod / Lambda）。整个 Spike 的算力成本大概在**两位数美元**。

**两个必须现在就注意的坑**：
- **磁盘只剩 52GB**。4K 视频吃得极快。管线里第一步就降采样到 1080p——特征匹配在 1080p 完全够用
- **模型许可**：`DA3-METRIC-LARGE` / `DA3-BASE` / `DA3-SMALL` 是 **Apache 2.0**（可商用）；
  更大的变体和 nested 系列是 **CC BY-NC 4.0**（不可商用）。
  **如果这东西以后想做成产品，从第一天就只用 Apache 2.0 那几个**，别等到跑通了才发现要换模型重测

## 四、唯一值得现在就设计好的数据结构

不管 Gate 1 成败，有一个东西是稳定的——**`TrailSegment`**：

```
TrailSegment
├── reconstruction     # 点云/网格 + 中心线（含尺度来源标记）
├── trajectories[]     # N 条，每条 = (s, d) 剖面 + 速度剖面 + 六自由度位姿（若有）
│   └── telemetry      # GPMF: 陀螺 400Hz / 加速度 200Hz / GPS 18Hz
├── semantics[]        # VLM 贴的标签：树根区/岩板/弯墙/跳台/分叉
└── outcomes[]         # 分段计时、平顺度（IMU 振动谱）
```

Gate 2 的所有"推荐"逻辑，本质上都只是**对这个结构的查询**。先把它定死，后面换模型、换重定位方案都不用重写。
